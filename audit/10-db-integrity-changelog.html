一、动机

pickthought 的想法数据库位于书籍目录（常在 FAT32 SD 卡）。FAT32 在意外断电 / 热插拔时易产生损坏页；此前 SQLite 层已有 WAL + 事务 + 文件清理，但缺 integrity_check、迁移追踪表、wal_checkpoint。缺 integrity_check 意味着损坏库会被直接打开、可能引发开书异常；WAL 模式下 -wal/-shm 长期留存也增大下次崩溃窗口与 IO 开销。本改动补齐这三块，对 KPW3 等低性能墨水屏设备的本地健壮性收益最高。

二、具体改动点

thought_db.lua 改动清单：

  • 新增 SCHEMA_VERSION 常量（当前 = 1），作为 schema 迁移基线。
  • 新增 get_user_version() / set_user_version(v)：用 PRAGMA user_version 记录 schema 版本（当前仅记录，不做破坏性迁移）。
  • 新增 ThoughtDB.integrity_check(db)：PRAGMA integrity_check 经 prepare+step 校验返回 ok，否则返回错误信息字符串。
  • 新增 ThoughtDB.checkpoint(db)：PRAGMA wal_checkpoint(TRUNCATE) 折叠 WAL 回主库并回收 -wal/-shm。
  • open 改为「打开即核验 + 损坏重建一次」：调用完整性校验，损坏则丢弃本地缓存（想法可由注入源重建）并重建成干净库；用内层 _attempt 包裹，仅重试一次防递归。
  • close 改为「关闭前 checkpoint」：先折叠 WAL 再关闭句柄，降低下次打开的 IO 与崩溃窗口。

tests 改动清单：

  • 新增 tests/test_thought_db_integrity.lua（6 case：校验通过 / 损坏重建 / 迁移写入 / user_version 读回 / checkpoint 调用 / 打开即核验）。
  • tests/stubs.lua：扩展 sqlite mock 支持 integrity_check / user_version（PRAGMA 分支只返回一次，避免无限循环）。
  • tests/run.lua：修 io.stdout:setvbuf("no") 使非 TTY 下汇总可见；注册 test_thought_db_integrity。

三、影响范围
