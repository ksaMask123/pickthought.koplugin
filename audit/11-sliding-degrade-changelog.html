一、动机

注入热路径（epub_inject.lua 的副本拷贝循环、sync.lua 的章节批量抓取）在 KPW3 等低性能墨水屏设备上可能长时间 CPU 满载，挤压阅读主线程的调度与刷新，造成卡顿甚至看门狗触发。既有代码用整秒 os.time() 计时，无法分辨 <1s 的慢单元，也没有「连续变慢即主动让出」的柔性降级机制。 本改动引入一个纯状态机的滑窗性能采样器：滑动窗口内统计单元处理耗时，连续 N 次超过阈值即置位「降级」标志；降级时在进度心跳 / 抓取节拍之间主动让出 CPU（生产默认 FFIUtil.usleep(150ms)），把算力交还阅读主线程，防卡顿。

三、具体改动点

performance_mode.lua（新增 125 行） 纯状态机，无 UIManager / KOReader 全局依赖，可在 worker 子进程与单元测试中通用：

  • M:new(opts) / M.default()：可注入 now_ms（单调毫秒时钟）与 rest（让出回调）；默认 window_s=600、slow_ms=1200、consecutive=2、rest_min_gap_ms=1000。
  • M:record(name, ms)：滑窗裁剪 + 连续慢计数；达到 consecutive 次即置位 _degraded。
  • M:degraded() / M:rest() / M:reset() / M:slow_count()：读取降级标志、执行让出（含墙钟节流）、复位全部状态、统计窗口慢单元数。
  • 字段刻意用 _degraded / _rest / _last_slow_ts / _last_rest_ts 命名，避免遮蔽同名元表方法。

修正点 1 · 让出解耦 progress epub_inject.lua（+7 行）：每单元用 perf:now() 打点、perf:record(...) 记录耗时；循环尾部独立于 opts.progress 执行 if perf:degraded() then perf:rest() end。让出在生产路径（无 progress 转发）也能触发。

修正点 2 · 移除 sync 网络计时 sync.lua：rebase 到干净 upstream/main（38c352c，无任何 perf 代码）后，sync.lua 现 0 处 performance_mode/perf: 引用（grep -c 实测 = 0）。网络耗时不再被当作本地慢样本。

修正点 3 · 窗口感知 streak record() 追踪 _last_slow_ts：仅当上一次慢样本仍在窗口内（now - _last_slow_ts ≤ window_s*1000）才续接连续计数，否则重置为 1。陈旧（已超出窗口）的慢样本不再把 slow_streak 推过阈值而误降级。用例：慢 → 越窗 → 再慢 → 不降级。

修正点 4 · rest 墙钟节流 rest() 新增墙钟节流：两次实际让出至少间隔 rest_min_gap_ms（默认 1000ms），被节流跳过时不调用 _rest。1615 条目书从累计约 242s 降到约 35s，让出次数由 1615 降到 ~231（用例：大书场景让出次数有界）。

八、2026-08-14 评审二轮（CHANGES_REQUESTED 最终轮，提交 aa758fb）

动机：作者复核上一轮（c77ef96）后指出两处生产正确性问题——「整秒精度漏降级」与「前台阻塞」。
具体改动：
  • 整秒精度漏降级：make_default_clock 原用整秒 os.time()，<1s 的慢单元无法触发降级。改为拆分 ffi/util.gettime() 的秒 + 微秒合成完整毫秒（math.floor(sec*1000 + usec/1000)），并加回拨保护（当前值小于上一次时钳制为非递减），避免系统时间回拨导致采样异常。
  • 前台阻塞：main.lua 的 _sync_run 前台 inject 包装传入 rest = function() end（no-op），禁用阻塞式让出（前台同步时不应 usleep 阻塞阅读主线程）；降级让出仅在 worker 子进程 / 后台任务路径生效。
测试补强：新增「default 时钟：拆分秒+微秒得完整毫秒 + 回拨保护」「default rest 用 fu.usleep；前台回退可替换为 no-op 非阻塞」两用例（注意清 package.loaded["ffi/util"] 缓存以加载新桩）。
影响范围：仅 performance_mode.lua 时钟实现与 main.lua 前台 injct 包装；注入产物内容不变，向后兼容。
