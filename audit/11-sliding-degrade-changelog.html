一、动机

注入热路径（epub_inject.lua 的副本拷贝循环、sync.lua 的章节批量抓取）在 KPW3 等低性能墨水屏设备上可能长时间 CPU 满载，挤压阅读主线程的调度与刷新，造成卡顿甚至看门狗触发。既有代码用整秒 os.time() 计时，无法分辨 <1s 的慢单元，也没有「连续变慢即主动让出」的柔性降级机制。 本改动引入一个纯状态机的滑窗性能采样器：滑动窗口内统计单元处理耗时，连续 N 次超过阈值即置位「降级」标志；降级时在进度心跳 / 抓取节拍之间主动让出 CPU（生产默认 FFIUtil.usleep(150ms)），把算力交还阅读主线程，防卡顿。

二、具体改动点

performance_mode.lua（新增） 纯状态机，无任何 UIManager / KOReader 全局依赖，可在 worker 子进程与单元测试中通用：

  • M:new(opts) / M.default()：可注入 now_ms（单调毫秒时钟）与 rest（让出回调）；默认 window_s=600、slow_ms=1200、consecutive=2。
  • M:record(name, ms)：滑窗裁剪 + 连续慢计数；达到 consecutive 次即置位 _degraded 并记录 degraded_since（降级为会话内粘性，仅 reset() 清除）。
  • M:degraded() / M:rest() / M:reset() / M:slow_count()：读取降级标志、执行让出、复位全部状态、统计当前窗口慢单元数。
  • 字段刻意用 _degraded / _rest 命名，避免遮蔽同名元表方法（修复：原先实例字段 degraded/rest 遮蔽方法导致 perf:degraded() 调用布尔值崩溃）。

epub_inject.lua 集成：

  • inject_copy 每单元用 perf:now() 打点、perf:record(entry.path, …) 记录耗时。
  • 降级时在 opts.progress 心跳前调用 perf:rest() 让出一次。

sync.lua 集成：

  • Sync.run 在每章 fetch 节拍前若 perf:degraded() 则 perf:rest()，抓取后 perf:record(ch.uid, …) 记录耗时。

tests 改动：

  • 新增 tests/test_performance_mode.lua（7 case：初始未降级 / 连续慢触发 / 快单元打断 / 滑窗裁剪 / reset 清除 / rest 注入回调 / default 字段），全部用注入伪时钟。
  • tests/run.lua：注册 test_performance_mode。

三、影响范围

  • 仅新增一个独立模块 performance_mode.lua，并在注入 / 同步热路径插入采样与可选让出；默认参数下非降级时行为与原版一致（仅多几次整数运算与表写入），不改变注入产物内容。
  • 不改变注入字节产出：不影响 EPUB 副本内容、数据库 schema、多书（D）逻辑。
  • 让出默认仅在降级时触发，且仅在进度心跳 / 抓取节拍边界执行，不会打断单次单元处理的原子性。
  • 不动 SQLite 层（④ 的改动范围），与 ④ 零文件冲突。
