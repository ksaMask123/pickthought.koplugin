2026-08-14
clean_source 逃生舱（只做 A，解卡点）
动机
原设计两处硬编码：① .orig 作为唯一干净源；② api:chapters 作为唯一章节枚举。当《神秘复苏》重注时原书已被注入（.orig 被污染）且本地无干净备份，Sync.run 直接报错退出，离线重注卡死。
决策
经评估，① 与 ② 的原始设计意图均合理（就地替换 + 自管理备份 的幂等模型；在线优先、权威章节对齐），应扩展逃生舱而非重写。仅实现 A（干净源逃生舱）解当前卡点；B（离线章节枚举）需新增 SQLite 下划线缓存（大改动），暂缓。
具体改动
  • Sync.run 新增可选 deps.clean_source（外部干净 .epub 路径），经存在性 / 非注入版 / 非自身 三项校验后，作为注入源绕开脏/缺失的 .orig。
  • 通过 deps.copy_file（默认 U.copy_file，带 Windows 覆盖回退）将干净源固化为 .orig 备份，且不破坏用户原书。
  • 固化失败（复制失败）致命且回滚：脏 doc_path 已先暂存为 .old，固化失败时回滚 .old → doc_path 保住用户当前书、不丢失数据（旧实现曾为「仅告警不致命」，详见下方 4a91c12 修复项）。
  • 报告表新增 clean_source 字段；默认行为完全不变（未传该参数时走既有路径）。
  • 测试：新增 tests/test_sync_clean_source.lua（6 case），并接入 tests/run.lua 的 files 列表。
影响范围
仅影响 Sync.run 的源选择分支；在线同步、划线/想法缓存（thought_db）、注入标记、UI 均未改动。无破坏性、向后兼容。

2026-08-14（再续）
修复 src==clean_source 重建时 swap 踩已存在目标失败 + 真机端到端验证
动机
将 clean_source 逃生舱 surgical port 到 KPW3 真机设备做端到端验证时，发现原实现在 src == clean_source 分支只固化 .orig、未移开脏 doc_path：脏注入版仍占着原路径，最终 rename(temp_dest, doc_path) 在「目标已存在即失败（不覆盖）」语义下报错 → 重注静默失败、用户无感知。
具体改动（提交 4a91c12）
  • 脏 doc_path 先 rename 为 .old 暂存，让出原路径；若 .old 残留先清理。
  • 固化 .orig 失败 → 回滚 .old → doc_path，保住用户当前书、不丢失数据（改为致命+回滚，而非旧版的「仅告警不致命」）。
  • swap 成功后 pcall(remove, .old) 清理暂存；swap 失败回滚优先用 .old（再 fallback backup）。
  • 与真机设备版实现逐字一致，确保设备已生效的行为与仓库 PR 同源。
测试补强
  • 更新原 clean_source 用例的 rename 计数断言：由「1 次换位」改为「2 次（脏版暂存 .old + 注入版顶上原路径）」。
  • 将「复制失败不致命」用例改为「固化失败回滚恢复原注入版」，与新语义一致。
  • 新增回归用例：模拟设备端 rename 不覆盖语义（目标已存在返回失败），断言脏 doc_path 先暂存为 .old、swap 成功、.old 最终被清理。
  • 全量测试：158 passed / 0 failed（较原 157 新增 1 回归用例）。
真机端到端验证（指令 1）
  • KPW3（Kindle PaperWhite 3）真机验证通过：以《神秘复苏》干净原书 + 本地离线 sync-cache 跑通 clean_source 重注。
  • 结果：1617 份缓存与 71,177 行想法无损还原，epub 内含 pickthought.json，防污染守卫有效。
  • crash.log 无报错，无 attempt to index ... (a nil value) 类崩溃。
  • 本结果已同步写入 PR #20 的说明（向原作者 Mr54233 表明已经过实机测试验证）。
