动机
原设计两处硬编码：① .orig 作为唯一干净源；② api:chapters 作为唯一章节枚举。当《神秘复苏》重注时原书已被注入（.orig 被污染）且本地无干净备份，Sync.run 直接报错退出，离线重注卡死。
决策
经评估，① 与 ② 的原始设计意图均合理（就地替换 + 自管理备份 的幂等模型；在线优先、权威章节对齐），应扩展逃生舱而非重写。仅实现 A（干净源逃生舱）解当前卡点；B（离线章节枚举）需新增 SQLite 下划线缓存（大改动），暂缓。

P1#3 干净原书不再被误删
clean source 流程先确认当前 doc_path 确为注入版（含 MARKER）；若仍是干净原书（如首次注入中途失败，仅有章节缓存），则保留为 .orig 备份而非丢进 .old 销毁，避免不同版本原书永久丢失。main.lua:_has_reinject_cache 增加 .orig 存在性守卫，干净原书不再误提供「重新注入」。
P2 映射缓存指纹纳入干净源

动机
作者在 2026-08-15 对 PR #20 提出第二轮（合并前）补充：异常文件保护、入口可达性、缓存失效边界四类问题。
P1 入口可达性：_has_reinject_cache 不强制 .orig
main.lua 的 _has_reinject_cache 原要求 .orig 存在才显示「重新注入」；现改为确认当前书含注入标记即显示入口（即使 .orig 丢失也能进 clean_source 逃生舱），同时隐藏干净原书入口，避免把干净原书当注入版误删。用 pcall(EpubReader.load) 安全判定，加载失败即隐藏（保守安全）。
P1 文件损坏保护：load_meta 区分不存在 vs 解析失败
Sync.run 开头先 current_meta, err = load_meta(doc_path)；当 doc_path 存在但解析失败（损坏）时，在任何 rename/copy 前直接中止，保证 doc_path / .orig / .old 均不被改动，明确报错「已损坏无法解析」。
P1 复制原子性：copy_file_stream 临时文件 + 回滚
util.lua 的 U.copy_file_stream 改为先写同目录临时文件（.copy.tmp），逐项校验读/写/flush/close；成功才原子替换最终目标（已存在则先暂存 .prev 以便失败回退）；取消或失败时清理临时文件并保留旧备份；on_progress 返回 false 即视为取消（第三返回值 "cancelled"）。Sync.run 固化失败分支识别取消状态，单独回滚 .old→doc_path 并提示。
P2 缓存失效：map_signature 加入内容指纹
util.lua 新增 U.content_fingerprint（FNV-1a 头尾 64KB 采样）；map_signature 由「大小@算法版本」升级为「大小@算法版本@指纹」，杜绝同体积不同内容复用旧映射；指定 clean_source 时强制废弃旧映射缓存（跳过解码）。

① 取消向上传递
Sync.run 复制阶段（默认 copy_file 包装器 U.copy_file_stream + step("copy")）被取消时返回 (nil,"已取消复制","cancelled")，Sync.run 据此中止，不继续 .orig 固化与原书 swap；新增回归用例验证「取消后不执行最终 swap、.old 回滚为 doc_path」。
② 恢复如实区分
换位失败恢复新增 recovered_from（"old" / "clean"）跟踪；提示与实际文件状态一致：恢复的是干净原书（.orig→doc_path）明确说「已恢复干净原书」，恢复的是旧注入版（.old→doc_path）明确说「已恢复旧注入版」，绝不谎称已恢复旧注入版。
③ 章节缓存仍可见入口

④ 统一注入基线
干净书 + 指定不同 clean_source 时：clean_source 固化为 .orig（与注入源一致），当前打开的干净原书暂存为 .old 保留（不销毁、不混入 .orig），避免版本不一致与误销毁；cancel / 固化失败回滚逻辑补齐。同步更新该项既有语义用例以匹配「统一注入基线」。
⑤ EOF 与读错区分 + .prev 回滚
U.copy_file_stream 读循环遇 rerr 返回「读取源文件失败」（半截副本不当成功备份）；.prev 回滚结果检查，回滚失败如实报错（不谎称成功）。
⑥ 缓存签名路径哈希
