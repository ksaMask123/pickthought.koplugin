P1#1 · addPath 返回 false 误报失败 P1 已修

文件
pickthought/epub_inject.lua · tests/test_epub_inject.lua
动机
KOReader 的 ZipWriter.addPath 到达 ZIP 末尾时可能返回 false 但 writer.err 为空（正常 EOF），旧代码据此误报「addPath 失败」导致大书注入中断。
改动
copy_entry_via_disk 中判定由 if not ok_add then return nil,"addPath" end 改为仅当 not ok_add and writer.err 时才报错；EOF 正常返回。
测试
新增「磁盘中转 addPath 返回 false 无 err 视为正常 EOF，不误报失败」：覆写 Arc.Writer.addPath 返回 false 且 self.err=nil，断言注入成功、大图逐字节写入、重命名次数=1。

P1#2 · 多书按书隔离预算/限速/连续失败 P1 已修

文件
pickthought/sync.lua · tests/test_sync.lua
动机
多书共用 fresh_fetches/rate_limited/consecutive_hard 全局状态，第一本耗尽预算或触发限速/熔断会拖垮后续书。
改动
  • 移除 fresh_fetches/consecutive_hard 全局变量，在 fetch_book 内局部化为 book_fresh_fetches/book_consecutive_hard/book_rate_limited/book_rate_limit_wait。
  • 章节列表拉取失败、连续失败熔断（≥3）在多书模式改为软失败：标记 per_book[bid].failed/error 并 return false，继续下一本；单书模式仍硬中止（return nil）。
  • fetch_book 结束后把本书限速状态聚合进报告级 rate_limited。
  • 主循环区分 nil（硬中止整批）/ false（本书软失败）：全部软失败且无任何章节数据时整体报错，否则注入成功部分。
测试
新增 3 例：① 多书限速——book1 限流、book2 照常；② 多书失败——book1 连续硬失败熔断、book2 完整注入；③ 小预算——book1 耗尽自身预算（2 章）停下，book2 仍取满自身 2 章（不被饿死）。

P1#3 · 多书重建合并所有有效缓存 P1 已修

文件
pickthought/sync.lua · tests/test_sync.lua
动机

测试
新增「多书重建合并所有有效缓存，新增书不丢旧书数据」：b001/b002 返回 resumed=true（缓存），b003 返回新数据，skip_resumed=true；断言三本书共 8 章全部合并注入（旧书缓存不丢）。
