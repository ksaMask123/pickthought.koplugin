原作者要求 / 背景（Mr54233）

在拆分前述 4 个性能 PR 时，作者曾表示「多书绑定暂不做」。但后续作者对已实现的多书绑定分支 表达出兴趣，希望看到实现，故本 PR 作为 Draft · RFC 提交，便于直接 review 多书注入的完整实现。

如何达成作者诉求

  • 把原本只支持单书注入的同步流程，扩展为多书绑定能力：用户可在「绑定」界面把多本书（≥2）绑定到同一组「想法」。
  • 注入时，spine 缓存、ChapterMap 匹配、thoughts SQLite 句柄均按 book_id 隔离，多本书的想法分别落到各自 book_id 下。
  • 跨书匹配：绑定组内任一书的章节都可命中组内其他书的想法，避免重复注入。
  • 配套继承了 PR② 对 epub_inject.lua 的两个必崩 bug 修复（addPath 参数错位、disk_tmp 遮蔽成 nil），确保大条目注入不崩。
  • 为让本 Draft 自包含、不依赖尚未合并的 PR #9~#12，本分支已内联这些性能优化的对应代码，作者可在单一分支看到多书特性的完整形态。
